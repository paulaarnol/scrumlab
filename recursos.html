GLOSARIO DE CALIDAD Y DESARROLLO DE SOFTWARE

Este glosario reúne conceptos fundamentales relacionados con el desarrollo, la evaluación y la mejora de productos de software. Su objetivo es facilitar la comprensión de términos técnicos utilizados durante las distintas etapas de un proyecto.

A

Accesibilidad

Capacidad de un sitio web o aplicación para ser utilizado por personas con diferentes capacidades, necesidades y formas de interacción.

Agilidad

Enfoque de trabajo que prioriza la colaboración, la entrega frecuente de resultados y la adaptación a los cambios durante el desarrollo de software.

Algoritmo

Conjunto ordenado y finito de instrucciones que permiten resolver un problema o realizar una tarea.

Análisis de requisitos

Proceso de identificar, estudiar y documentar las necesidades y condiciones que debe cumplir un sistema.

Aseguramiento de la calidad

Conjunto de actividades planificadas que buscan garantizar que los procesos y productos de software cumplan con los requisitos de calidad establecidos.

Auditoría de software

Revisión sistemática de un producto o proceso para comprobar si cumple con determinados requisitos, normas o procedimientos.

B

Backlog

Lista priorizada de tareas, funcionalidades, mejoras y correcciones pendientes de realizar en un proyecto.

Base de datos

Conjunto organizado de datos que pueden almacenarse, consultarse, modificarse y administrarse mediante un sistema informático.

Bug

Error o defecto que puede provocar que un programa funcione de manera incorrecta o produzca resultados inesperados.

Caja blanca

Técnica de prueba que examina la estructura interna, el código y los caminos de ejecución de un programa.

Caja negra

Técnica de prueba que evalúa las entradas y salidas de un sistema sin necesidad de conocer su código interno.

Calidad del software

Grado en que un producto de software cumple con los requisitos establecidos y satisface las necesidades de sus usuarios.

C

Caso de prueba

Conjunto de condiciones, datos de entrada, pasos y resultados esperados que se utiliza para comprobar una funcionalidad.

Ciclo de vida del software

Conjunto de etapas por las que pasa un producto de software, desde la identificación de una necesidad hasta su mantenimiento y evolución.

Codificación

Etapa en la que se escribe el código fuente que implementa las funcionalidades diseñadas para un sistema.

Compatibilidad

Capacidad de un software para funcionar correctamente con otros sistemas, dispositivos, programas o entornos.

Complejidad

Grado de dificultad que presenta un sistema o programa para comprenderlo, desarrollarlo, probarlo o mantenerlo.

Corrección de errores

Proceso de identificar y solucionar defectos que afectan al funcionamiento esperado de un programa.

Criterios de aceptación

Condiciones que una funcionalidad debe cumplir para considerarse terminada y aceptable según las necesidades del usuario.

D

Daily Scrum

Reunión breve de Scrum en la que los Developers inspeccionan el progreso hacia el objetivo del Sprint y ajustan su plan de trabajo.

Depuración (debugging)

Proceso de localizar, analizar y corregir errores en el código de un programa.

Desarrollo incremental

Enfoque en el que un producto se construye mediante entregas sucesivas, incorporando nuevas funcionalidades en cada incremento.

Desarrollo iterativo

Enfoque que mejora progresivamente una solución mediante ciclos repetidos de construcción, evaluación y ajuste.

Diseño de software

Actividad que define la estructura, los componentes, las interfaces y las decisiones técnicas necesarias para construir un sistema.

Documentación

Conjunto de textos, diagramas e instrucciones que describen el funcionamiento, la estructura, el uso o el mantenimiento de un software.

E

Eficiencia

Capacidad de un sistema para ofrecer los resultados esperados utilizando adecuadamente recursos como el tiempo de procesamiento y la memoria.

Error

Equivocación humana o técnica que puede introducir un defecto en el software.

Escalabilidad

Capacidad de un sistema para adaptarse al aumento de usuarios, datos o carga de trabajo sin perder un nivel de funcionamiento adecuado.

Estándar

Conjunto de criterios, reglas o especificaciones establecidos para orientar y unificar procesos o productos.

F

Fiabilidad

Capacidad de un sistema para funcionar correctamente y mantener su comportamiento esperado durante determinadas condiciones y períodos de uso.

Framework

Estructura de software que proporciona herramientas, componentes y reglas para facilitar el desarrollo de aplicaciones.

Funcionalidad

Capacidad de un producto para ofrecer las funciones que necesita el usuario y cumplir los requisitos establecidos.

G

Gestión de calidad

Actividades y procedimientos destinados a planificar, controlar, asegurar y mejorar la calidad de un producto o proceso.

Git

Sistema de control de versiones que permite registrar cambios en los archivos de un proyecto y recuperar versiones anteriores.

GitHub

Plataforma que permite alojar repositorios Git y colaborar en proyectos mediante herramientas de seguimiento, revisión y gestión del código.

H

Hardware

Componentes físicos de una computadora o dispositivo, como el procesador, la memoria y los dispositivos de almacenamiento.

Historia de usuario

Descripción breve de una necesidad o funcionalidad desde la perspectiva de quien utilizará el sistema.

I

Implementación

Etapa en la que una solución se desarrolla o se pone en funcionamiento en el entorno previsto, según el contexto del proyecto.

Incidencia

Suceso o problema detectado durante el uso, desarrollo o prueba de un sistema que requiere análisis o seguimiento.

Integración

Proceso de combinar componentes o módulos para verificar que funcionen correctamente en conjunto.

Interfaz de usuario (UI)

Elementos visuales e interactivos mediante los cuales una persona utiliza una aplicación o sistema.

Iteración

Ciclo de trabajo en el que se realiza una parte del desarrollo, se evalúa el resultado y se introducen mejoras.

K

Kanban

Método visual de gestión del trabajo que permite observar el estado de las tareas, controlar el flujo y detectar acumulaciones de trabajo.

Kit de desarrollo de software (SDK)

Conjunto de herramientas, bibliotecas y recursos que facilitan la creación de aplicaciones para una plataforma determinada.

L

Legibilidad

Facilidad con la que se puede leer y comprender un texto, una interfaz o un código fuente.

Linter

Herramienta que analiza código fuente para detectar posibles errores, inconsistencias y problemas de estilo.

Lista de tareas

Conjunto de actividades pendientes que deben realizarse para alcanzar un objetivo o completar una parte del proyecto.

M

Mantenibilidad

Facilidad con la que un software puede analizarse, corregirse, modificarse o mejorarse después de su desarrollo.

Manifiesto Ágil

Declaración que establece cuatro valores y doce principios para orientar el desarrollo ágil de software.

Metodología de desarrollo

Conjunto de prácticas, actividades y criterios que organizan el proceso de construcción de un producto de software.

Modelo en cascada

Modelo de desarrollo que organiza las etapas del proyecto de manera secuencial, avanzando de una fase a otra.

Modelo en V

Modelo que relaciona las etapas de desarrollo con actividades de verificación y validación correspondientes.

Modelo iterativo e incremental

Enfoque que combina ciclos de mejora sucesivos con entregas progresivas de funcionalidades.

N

No conformidad

Incumplimiento de un requisito, criterio, norma o condición previamente establecida.

O

Objetivo del Sprint

Propósito principal que el equipo Scrum busca alcanzar durante un Sprint.

Open source (código abierto)

Modelo de distribución de software cuyo código fuente está disponible bajo una licencia que permite determinados usos, modificaciones y redistribuciones.

P

Pair programming (programación en pareja)

Práctica de XP en la que dos programadores trabajan juntos sobre una misma tarea, compartiendo la escritura y revisión del código.

Planificación

Actividad que permite definir objetivos, tareas, recursos, prioridades y tiempos necesarios para desarrollar un proyecto.

Portabilidad

Capacidad de un software para trasladarse y funcionar en diferentes plataformas o entornos con un esfuerzo razonable.

Product Backlog

Lista ordenada de todo lo que se conoce como necesario para mejorar el producto en Scrum.

Product Owner

Responsable de maximizar el valor del producto y de gestionar eficazmente el Product Backlog en Scrum.

Prueba de integración

Prueba que comprueba la interacción entre dos o más componentes de un sistema.

Prueba de sistema

Prueba que evalúa el sistema completo para verificar si cumple con los requisitos especificados.

Prueba unitaria

Prueba que verifica una unidad pequeña de código, como una función o un método, de forma aislada.

Q

QA (Quality Assurance)

Sigla de *Quality Assurance*, que significa aseguramiento de la calidad. Comprende actividades destinadas a prevenir problemas y mejorar los procesos que producen software.

R

Refactorización

Modificación de la estructura interna del código para mejorar su claridad o mantenimiento sin cambiar su comportamiento externo esperado.

Requisito

Necesidad, condición o capacidad que un sistema debe cumplir.

Retrospectiva del Sprint

Evento de Scrum en el que el equipo analiza cómo trabajó durante el Sprint e identifica mejoras para el siguiente ciclo.

Revisión del Sprint (Sprint Review)

Evento de Scrum en el que se inspeccionan los resultados del Sprint y se evalúan posibles ajustes futuros del producto.

Riesgo

Situación incierta que, si ocurre, puede afectar los objetivos, los plazos, los costos o la calidad de un proyecto.

Rol

Conjunto de responsabilidades y funciones asignadas a una persona o grupo dentro de una organización o metodología de trabajo.

S

Scrum

Marco de trabajo ágil que organiza el desarrollo en Sprints y utiliza eventos, responsabilidades y artefactos para facilitar la inspección y la adaptación.

Seguridad

Capacidad de un sistema para proteger la información y los recursos frente a accesos, modificaciones o acciones no autorizadas.

Sistema de gestión de calidad

Conjunto de políticas, procesos y responsabilidades que una organización utiliza para gestionar y mejorar la calidad.

Software

Conjunto de programas, instrucciones y datos que permiten a un dispositivo realizar determinadas tareas.

Sprint

Período de duración fija en Scrum durante el cual se trabaja para alcanzar un objetivo y producir un incremento de producto utilizable.

Sprint Backlog

Objetivo del Sprint, conjunto de elementos seleccionados del Product Backlog y plan de trabajo para entregar el incremento.

Stakeholder (parte interesada)

Persona, grupo u organización que puede afectar al proyecto o verse afectado por sus resultados.

T

TDD (Test-Driven Development)

Práctica de desarrollo en la que se escribe primero una prueba, luego el código necesario para superarla y después se mejora la implementación.

Test case

Expresión en inglés equivalente a caso de prueba: conjunto de pasos, condiciones y resultados esperados para verificar un comportamiento.

Tester

Persona que planifica o ejecuta pruebas para detectar defectos y comprobar que el software cumpla los requisitos.

Testing (pruebas de software)

Proceso de evaluar un sistema o sus componentes para detectar defectos y verificar su comportamiento frente a los requisitos.

Trazabilidad

Capacidad de relacionar requisitos con su diseño, implementación, pruebas y resultados para realizar un seguimiento de su cumplimiento.

U

Usabilidad

Grado en que un sistema puede ser utilizado por usuarios determinados para alcanzar objetivos de manera eficaz, eficiente y satisfactoria en un contexto de uso.

Usuario

Persona que utiliza o interactúa con un sistema de software para realizar una tarea o satisfacer una necesidad.

V

Validación

Proceso de comprobar si el producto desarrollado satisface las necesidades y expectativas de los usuarios.

Verificación

Proceso de comprobar si un producto o resultado cumple los requisitos y especificaciones establecidos.

Versión

Estado identificado de un software en un momento determinado de su evolución.

W

WIP (Work in Progress)

Cantidad de tareas que se encuentran en proceso de realización. En Kanban, limitar el WIP ayuda a evitar la sobrecarga y mejorar el flujo de trabajo.

Workflow (flujo de trabajo)

Secuencia organizada de actividades y estados por los que pasa una tarea o proceso hasta completarse.

X

XP (Extreme Programming)

Metodología ágil que promueve prácticas de ingeniería como programación en pareja, pruebas frecuentes, integración continua y refactorización.

Y

Yield (rendimiento o producción)

En determinados contextos informáticos, término utilizado para referirse a resultados producidos o a la cesión del control de ejecución. Su significado concreto depende del contexto técnico.

Z

Zero-day (día cero)

Vulnerabilidad de seguridad desconocida o para la que todavía no existe una solución disponible en el momento en que se detecta o comienza a explotarse.
