GESTIÓN DE CALIDAD DEL SOFTWARE

Comprendé los conceptos fundamentales de la calidad del software, las métricas utilizadas para evaluarla y los principales estándares relacionados.

¿Qué es la calidad del software?

La calidad del software permite evaluar si un producto cumple con los requisitos establecidos y si responde de manera adecuada a las necesidades de sus usuarios.

CONCEPTOS CLAVES

CALIDAD

Grado en que un producto de software cumple con los requisitos y características esperadas.

MÉTRICA

Medida utilizada para evaluar diferentes aspectos de un producto o proceso de software.

ESTÁNDAR

Conjunto de criterios o normas que sirven como referencia para evaluar o desarrollar software.

MÉTRICAS DE CALIDAD

Las métricas permiten obtener medidas sobre diferentes características del software y ayudan a evaluar su calidad de manera más objetiva.

  • Funcionalidad: Que el software cumpla correctamente con las funciones para las que fue creado.
  • Fiabilidad: Capacidad de funcionar correctamente y de manera estable, sin fallos frecuentes.
  • Usabilidad: Facilidad con la que el usuario puede aprender y utilizar el software.
  • Eficiencia: Capacidad de realizar sus funciones aprovechando adecuadamente los recursos disponibles.
  • Mantenibilidad: Facilidad para corregir, actualizar o modificar el software cuando sea necesario.
  • Portabilidad: Capacidad de funcionar en diferentes sistemas, plataformas o entornos.

ESTÁNDARES DE CALIDAD

ISO 9126 / ISO 25000

ISO 9126: Define la calidad a través de 6 características principales (Funcionalidad, Fiabilidad, Usabilidad, Eficiencia, Mantenibilidad y Portabilidad).

TÉCNICAS DE ASEGURAMIENTO DE LA CALIDAD

Las pruebas de software permiten comprobar el funcionamiento de un sistema, detectar errores y verificar que cumpla con los requisitos establecidos.

NIVELES DE PRUEBAS

Las pruebas pueden realizarse en diferentes niveles, dependiendo de la parte del software que se quiera evaluar. Pasa el cursor o toca una tarjeta para ver más información.

01 | PRUEBAS UNITARIAS

Se comprueban componentes individuales del software para verificar que funcionen correctamente de manera aislada.

• Objetivo: Comprobar el funcionamiento de cada componente.
01 | MÁS INFORMACIÓN
  • Ejecutado por: Desarrolladores.
  • Técnicas: Mocks, Stubs, Assertions.
  • Herramientas: JUnit, PyTest, Jest, NUnit.
  • Momento: Fase de codificación temprana.
02 | PRUEBAS DE INTEGRACIÓN

Se verifica la interacción entre diferentes componentes del software para comprobar que funcionen correctamente en conjunto.

• Objetivo: Detectar problemas en la comunicación entre componentes.
02 | MÁS INFORMACIÓN
  • Ejecutado por: Desarrolladores o QA.
  • Enfoques: Top-Down, Bottom-Up, Big Bang.
  • Herramientas: Postman, RestAssured, SoapUI.
  • Foco: Interfaces y contratos de datos.
03 | PRUEBAS DE SISTEMA

Se evalúa el sistema completo para comprobar que funcione correctamente y cumpla con los requisitos establecidos.

• Objetivo: Comprobar el funcionamiento general del sistema.
03 | MÁS INFORMACIÓN
  • Ejecutado por: Equipo de QA independiente.
  • Tipos: Funcionales, Rendimiento, Seguridad.
  • Herramientas: Selenium, Cypress, JMeter.
  • Entorno: Staging / Pre-producción.

TIPOS DE PRUEBAS

Además de los niveles, las pruebas pueden clasificarse según la forma en que se analiza el software.

CAJA NEGRA

Evalúa el comportamiento del software a partir de las entradas y los resultados obtenidos, sin centrarse en su funcionamiento interno.

CAJA BLANCA

Analiza el funcionamiento interno del software, teniendo en cuenta su lógica y estructura.

HERRAMIENTAS DE CALIDAD

Conocé algunas herramientas utilizadas para gestionar pruebas, realizar el seguimiento de errores y analizar la calidad del software.

CATEGORÍAS DE HERRAMIENTAS

Bug Trackers: Permiten registrar, organizar y hacer seguimiento de errores encontrados durante el desarrollo.
Linters: Analizan el código para detectar errores, problemas de estilo o posibles mejoras.
Test Management: Facilitan la planificación, organización y seguimiento de las pruebas de software.

Bug Trackers

JIRA

Permite registrar, organizar y realizar el seguimiento de errores y tareas durante el desarrollo de un proyecto.
Ayuda al equipo a controlar los problemas encontrados y conocer su estado, por ejemplo: pendiente, en proceso o resuelto.

BUGZILLA

Herramienta destinada al registro y seguimiento de errores encontrados en un sistema.
Permite asignar errores, agregar información y realizar un seguimiento hasta su resolución.

Linters

ESLINT

Analiza el código para detectar errores, problemas de escritura y posibles mejoras.
Se utiliza principalmente con JavaScript y ayuda a mantener un código más ordenado y consistente.

STYLELINT

Analiza archivos CSS para detectar errores y problemas relacionados con la escritura del código.
Permite encontrar problemas de estilo y mantener reglas de formato dentro de un proyecto.

Test Management

TESTRAIL

Permite organizar, gestionar y realizar el seguimiento de casos y actividades de prueba.
Ayuda a planificar las pruebas y registrar sus resultados para conocer qué casos fueron ejecutados y cuáles necesitan atención.

ZEPHYR

Herramienta para planificar y administrar pruebas de software dentro de un proyecto.
Permite organizar casos de prueba, controlar su ejecución y realizar un seguimiento de los resultados.
